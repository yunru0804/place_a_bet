# 🎰 Place a Bet：派對下注網站

給十幾個人的聚會用的下注與小遊戲網站。架在自己電腦上，大家用手機打開專屬連結就能玩，畫面是賭場風格。

- 每人 1000 點，可以押一般盤，也能在 PK 小遊戲裡押誰會贏
- 分成紅、黃、綠、藍四隊，有團體賽（拔河、跳繩、開香檳），勝隊自動加分
- 主持人在後台開盤、結算、發點數、看排行榜
- 不用帳號密碼：每位玩家一條專屬連結
- 一個 SQLite 檔案就是全部資料，備份就是複製一個檔

技術：Python、FastAPI、SQLite、Jinja 模板，即時對戰走 WebSocket。前端不用打包工具，也沒有前端框架。

---

## 快速開始

需要 Python 3.10 以上。

```sh
git clone <這個 repo>
cd place_a_bet
./run.sh
```

第一次執行會：

1. 建立 `.venv` 並安裝套件
2. 在 `instance/` 產生資料庫、管理員密碼和 session 金鑰
3. 在終端機印出管理員密碼

接著打開 <http://127.0.0.1:8000/admin> 登入後台。

### 讓外面的人連進來（ngrok）

網站只聽本機 `127.0.0.1:8000`，用 [ngrok](https://ngrok.com/) 開一條對外通道：

```sh
brew install ngrok
ngrok config add-authtoken <你的 token>
ngrok http 8000 --url=<你在 ngrok 後台領的固定網域>
```

之後從 `https://<你的網域>/admin` 進後台，複製出來的玩家連結就會是這個網址。

- 免費版第一次打開會先看到 ngrok 的警告頁，按「Visit Site」就能進去。
- 活動期間電腦不能睡眠，可以另開一個終端機執行 `caffeinate -i`。

## 玩法

### 點數規則

| 項目 | 規則 |
|---|---|
| 初始點數 | 每人 1000 點 |
| 每注 | 10 到 1000 點，不能超過自己的餘額。開盤期間可以改注 |
| 押對 | 拿回 2 倍 |
| 押錯 | 沒收 |
| 作廢 | 全額退還 |
| 出局 | 剩不到 10 點就出局；之後有加分（例如隊伍贏了）就能復活 |

### 三種盤

**一般盤**：主持人自訂題目和 A、B 兩個選項 → 下注 → 關盤 → 主持人按「A 正確」或「B 正確」。

**⚡ PK 盤**：從下拉選單選一個遊戲 → 全員投票（不能投自己，可以改票）→ 得票前 2 名上場，同票隨機抽 → 下注押誰贏，兩位選手只能押自己 → 關盤 → 比賽 → 自動結算。

| 遊戲 | 玩法 | 判定 |
|---|---|---|
| ⚡ 連打大賽 | 10 秒內誰點得多 | 自動 |
| 🚦 反應力對決 | 變綠時搶先按，偷跑直接輸掉該回合，先拿 2 勝 | 自動 |
| ⏱ 停錶挑戰 | 3 回合，目標 5 秒、10 秒、20 秒；碼表 2 秒後消失，累計差距小的贏 | 自動 |
| 🧮 搶答心算 | 10 題四選一，先答對得分，答錯就鎖住該題 | 自動 |
| 🧠 記憶挑戰 | 10 回合，照色塊閃爍的順序按，累計秒數少的贏，按錯會罰秒 | 自動 |
| 🎭 閃現辨識 | 窗簾一開，emoji 飛過，從 6 個長得很像的 emoji 選出剛剛那個；越來越快，窗簾開口也越來越小 | 自動 |
| 🎤 現場對決 | 現場比賽，網站只負責投票和下注 | 主持人按勝負 |

自動判定的遊戲如果平手，該輪作廢退還。

**🪢 團體賽**：選遊戲與兩隊 → 主持人按開始 → 兩隊全員一起在手機上玩 → 勝隊每位成員自動加 500 點。不開放下注，輸的隊伍不扣點。

| 遊戲 | 玩法 |
|---|---|
| 🪢 拔河 | 全員狂點把繩結拉向自己，先拉過線的贏；依人數平均，人少不吃虧 |
| 🤸 跳繩 | 跟著繩拍按「跳」；連續跳過連跳加成，全隊同一拍都跳過再加齊跳分；時間到比總分 |
| 🍾 開香檳 | 全員搖手機把瓶子搖到泡沫噴出，先爆開的贏 |

- 不計時，一定要有一隊把繩結拉過線才結束。卡住的話，主持人可以按作廢。
- 每一下的拉力等於 2 除以隊伍人數，比的是人均速度，所以隊伍人數不同也公平。舉例：4 人的隊伍，每人每秒比對手多點 1 下，大約 50 秒會拉到底。
- 每人每秒最多計 20 下。結束時會公布兩隊的 MVP。

### 主賽

四隊在現場 PK。主持人在後台「發放點數」區按「某隊勝利」，該隊每位成員加 500 點。也可以自訂發放或扣點，發錯了可以撤銷。

## 後台功能

- **開盤**：一般盤、PK 盤、團體賽三選一
- **即時看下注**：每個人押了什麼、押多少，PK 盤投票中會顯示得票數，每 3 秒自動更新
- **比賽觀戰**：PK 和團體賽進行中，後台也能即時看到比賽畫面
- **發放點數**：四隊一鍵加 500，或自訂發給隊伍或個人，每筆都能撤銷
- **排行榜**：用總點數排名，同分並列（例如 1、1、3）；有獨立的投影用頁面，網址是 `/admin/leaderboard`
- **玩家管理**：新增玩家、換隊、複製專屬連結、重設連結、刪除玩家
- **重新開始**：清空所有點數和紀錄，保留玩家和連結；執行前會自動備份

## 專案結構

```
app.py              路由：玩家頁 /p/<token>、後台 /admin、WebSocket /ws
db.py               資料表、遷移、所有點數與下注規則
game.py             相容入口（轉接到 pk.hub）
pk/
  base.py           BaseGame / TeamGame / 判定工具
  hub.py            WebSocket 廣播與一場進行中的遊戲
  registry.py       自動掃描 pk/games/
  games/            一款遊戲一個檔（名稱、規則、前端 JS 都在這裡）
templates/
  player.html       玩家頁
  admin.html        後台
  _pk_arena.html    PK／團體賽擂台殼（共用連線與倒數；各遊戲畫面由 CLIENT_JS 注入）
  _live.html        後台即時下注／投票區塊
  _board.html       排行榜區塊
static/style.css    樣式（會內嵌進每個頁面，見下方說明）
run.sh              啟動腳本
instance/           執行時資料：bets.db、admin_password.txt、secret_key.txt、backups/（不進版控）
```

### 設計重點

- **點數不另外存**：餘額每次從下注紀錄和發放紀錄（`adjustments` 表）推算，所以不會出現對不上帳的情況，每一筆變動都查得到來源。
- **同時只會有一輪進行中**：用資料庫的唯一索引保證。下注和關盤都在 `BEGIN IMMEDIATE` 交易裡處理，避免競態。
- **伺服器說了算**：PK 遊戲的計分和判定都在伺服器做。答案、記憶順序、對手秒數都等到公布時才送出。需要量反應時間的遊戲（反應力、停錶、閃現辨識）由手機自己量測，網路延遲才不會影響公平性。
- **樣式內嵌**：CSS 直接嵌進 HTML。透過 ngrok 免費版時，獨立的 CSS 請求可能被警告頁攔下，畫面就會變成白底。
- **自動遷移**：啟動時會檢查資料表，舊版資料庫會自動補上新欄位，資料不會遺失。

### 調整參數

| 想改的 | 位置 |
|---|---|
| 初始點數、下注上下限、主賽／團體賽獎金 | `db.py` 開頭的 `INITIAL_POINTS`、`MIN_BET`、`MAX_BET`、`MAIN_MATCH_PRIZE`、`TEAM_MATCH_PRIZE` |
| 隊伍名稱 | `db.py` 的 `TEAMS` |
| 遊戲名稱、說明、難度、畫面 | `pk/games/<遊戲>.py`（只改這一個檔） |
| 各遊戲的回合數、時間、難度 | 該遊戲類別開頭的常數，例如 `FlashGame.GAP`、`TugGame.PULL` |
| 閃現辨識的 emoji 組 | `pk/games/flash.py` 的 `EMOJI_GROUPS` |

### 新增一個 PK 小遊戲

在 `pk/games/` 新增一個 `.py`（會自動被掃進去），繼承 `BaseGame`（團體賽用 `TeamGame`），設定：

- `key` / `title` / `description` / `order`
- `team = True` 若是團體賽
- `run()`、`handle()`、`public()`、`outcome()`
- `CLIENT_JS`：寫入 `G.<key>`，實作 `label`、`panels`、`render`（選填 `tick`）

不必改 `db.py` 或 `_pk_arena.html`。現場對決這種沒有手機引擎的，設 `engine = False`（見 `live.py`）。

## 資料與安全

- `instance/` 裡有資料庫、管理員密碼和 session 金鑰，**不要上傳**，`.gitignore` 已經排除。
- 管理員密碼可以直接改 `instance/admin_password.txt`，或設定環境變數 `ADMIN_PASSWORD`。
- 玩家連結就是登入憑證。連結外流的話，到後台按「重設」，舊連結就會失效。
- **備份**：複製 `instance/bets.db` 就好。按「重新開始」或刪除玩家前，系統會自動備份到 `instance/backups/`。

## 已知限制

- 這是單一程序、單機使用的設計。比賽狀態存在記憶體裡，比賽進行中如果重啟伺服器，那一輪會卡在「比賽中」，到後台按「作廢」就能退還。
- 目前是為十幾人的規模設計，沒有考慮多台伺服器或大量連線。
